# 🎵 B站音频语音条点歌（bili_audio_sender）v1.1.2

一个给 **KiraAI** 机器人用的插件：把 **B 站视频的音频**下载下来，直接发成 **QQ 语音条**。

> 你说一句"来一首《极乐净土》"，机器人自己搜 B 站、挑一个、下载、然后你的 QQ 里就出现一条语音。就这么简单。

---

## ✨ 它能干什么

| 你这样做 | 机器人会 |
|----------|----------|
| 说 **"来一首XXX" / "点歌"** | 自动搜索 B 站，返回候选列表，自己挑一个发语音条（或发给你选） |
| 发一个 **B站链接 / BV号**（如 `b23.tv/xxxx`） | 直接下载音频转成语音条发出来 |
| 说 **`/点歌 关键词`** | 不走 AI，直接搜+发，秒出 |

三种方式都支持，按你的习惯来。

**示例 1：自然语言点歌（默认开启）**

```
你：来一首极乐净土
机器人：B站搜索「极乐净土」结果：
1. 【Miume・MARiA・217】极乐净土…｜GARNiDELiA｜BV1us41137Fd
2. …
（机器人挑了一个，直接发来一条语音条）
```

**示例 2：丢链接（需要在配置里开启"链接自动转语音"）**

```
你：https://b23.tv/xxxxxx 转成语音条
机器人：（直接发来一条语音条，AI 都不出场）
```

**示例 3：命令词（需要在配置里开启）**

```
你：/点歌 米津玄师
机器人：（直接发来一条语音条）
```

## 📦 安装方法（小白版，3 步）

1. **下载** 整个 `bili_audio_sender` 文件夹（里面有 `main.py`、`bili_dl.py`、`manifest.json`、`schema.json`、`requirements.txt`）。
2. **上传** 到你的服务器上 KiraAI 的 `data/plugins/` 目录里（跟其他插件放一起，文件夹名字别改）。
3. **启用**：在 KiraAI 的插件管理/配置面板里找到「B站音频语音条」打开开关；或者重启 KiraAI 让它自动加载。

> 💡 不需要手动装任何依赖。插件只用了 KiraAI 自带的 httpx 库，`requirements.txt` 只是保险声明，自动安装也不会出错。

## ⚙️ 配置说明（看不懂的可以全部不动，默认就能用）

**基础设置**

| 配置项 | 默认 | 说明 |
|--------|------|------|
| 启用插件 | 开 | 总开关 |
| 启用LLM工具调用(自然语言) | **开** | 让机器人能听懂"来一首XXX"。关掉后只能靠命令词 |
| 启用命令词触发 | 关 | 打开后才能用 `/点歌` `/下音频` |
| 命令词列表 | `/点歌`、`/下音频` | 每行一个，想加就加 |
| 链接自动转语音 | 关 | 打开后，发 B站链接就直接出语音条，**不额外消耗 token**。原始链接消息仍会进入 LLM 上下文，但会附带系统提示标注"已自动转语音条"，LLM 不会重复处理 |
| 严格意图校验 | 开 | 防止误伤：消息里必须带"下载/语音/音频"等词才拦截链接 |

**权限白名单（多人用的时候建议设置）**

| 配置项 | 默认 | 说明 |
|--------|------|------|
| QQ号白名单 | 空 | 空 = 谁都能用；填了 = 只有这些 QQ 号能用 |
| 群号白名单 | 空 | 空 = 所有群都能用；填了 = 只有这些群能用 |
| 无权限提示语 | 默认文案 | 没权限的人会看到这句话 |

**搜索与候选**

| 配置项 | 默认 | 说明 |
|--------|------|------|
| 候选条数 | 5 | 搜索时返回几条候选 |
| 自动选播放量最高直发 | 关 | 开 = 机器人搜完直接发播放量最高的，不给你挑；关 = 机器人自己挑或发给你选 |
| 返回视频简介 | 关 | 开 = 发送时带上视频简介文字 |
| 简介截断字数 | 100 | 简介最多显示多少字 |

**下载**

| 配置项 | 默认 | 说明 |
|--------|------|------|
| 最长音频秒数 | 600 | 超过 10 分钟的视频**不下载**（QQ 语音条太长会发不出去），下载前就会拦住 |
| 请求超时秒数 | 60 | 网络请求超时时间 |
| 网络代理模式 | auto | **auto**=先直连，网络失败自动走系统代理重试（国内外自适应）；**direct**=始终直连（国内用户，不读系统代理）；**system**=始终走系统代理（海外用户访问B站需要） |
| 缓存目录(相对data/) | `files/bili_cache` | 音频缓存放哪。同一条视频重复点会走缓存，不重新下载 |
| 缓存文件上限 | 50 | 缓存文件超过这个数，自动清理最旧的文件 |
| 单次清理数量 | 20 | 每次触发清理时删掉最旧的多少个文件 |
| B站Cookie(可选) | 空 | 如果经常报 B 站风控错误，把浏览器里登录 B 站的 Cookie 填进来（可选） |

## ❓ 常见问题（FAQ）

**Q：机器人没反应？**
A：先确认插件已启用；如果是命令词/链接方式，检查对应的开关有没有打开。

**Q：提示"你不在本功能白名单内"？**
A：配置里的 QQ号/群号白名单限定了可用范围。要么把自己的 QQ/群号加进去，要么把白名单清空（清空 = 不限制）。

**Q：提示"视频时长 XXXs 超过上限"？**
A：视频太长（默认超过 10 分钟）不会下载。在配置里调大"最长音频秒数"，或者换个短视频。

**Q：提示"当前会话不是QQ"？**
A：这个插件只支持 QQ 平台，别的平台（微信/飞书等）用不了。

**Q：报 B 站风控（-412）错误？**
A：B 站对高频请求有限制。在配置里填上你浏览器登录 B 站的 Cookie（`section_download` → `cookie`），能大幅降低触发概率。

**Q：语音条发不出去/提示发送失败？**
A：大概率是音频太长或太大（QQ 语音条有长度限制）。把"最长音频秒数"调小一点试试。

**Q：会不会占用很多 token / 流量？**
A：刻意做得很省。丢链接直发完全不经过 AI（0 token）；自然语言点歌只让 AI 调用一次工具；同一条视频重复点会走缓存，不再重新下载。

## 📝 技术说明（给好奇的人）

- **下载通道**：直接调 B 站官方 API（`view` → `playurl` → DASH 音频流），不依赖 yt-dlp，也不用 ffmpeg。
- **反爬兜底**：接口被风控时自动切换 **WBI 签名** 方案重试，稳定性更好。
- **发送方式**：音频以 QQ 语音消息（record）直接发送，不需要 AI 生成复杂指令，出错点更少。
- **运行环境**：Python 3.9+，仅依赖 `httpx`（KiraAI 自带）。
